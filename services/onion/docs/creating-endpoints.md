# Creating Endpoints in Onion

This guide documents the full flow to create an endpoint, from proto definition to wiring it into the server.

## 1. Define the Proto (grimoire)

Create or edit a `.proto` file in the grimoire repo under `proto/<scope>/<domain>/v1/`.

**Scopes:**
- `common/` — truly shared types (Error, Pagination)
- `shared/` — shared across platforms (account, config, core, translation)
- `voxire/` — Voxire platform-specific
- `rtylr/` — Rtylr platform-specific
- `autochannel/` — Autochannel platform-specific

**Example:** `grimoire/proto/shared/account/v1/login.proto`

```protobuf
syntax = "proto3";
package shared.account.v1;

message LoginRequest {
  string email = 1;
  string password = 2;
}

message LoginResponse {
  string token = 1;
  string message = 2;
  int64 user_id = 3;
  string email = 4;
  string name = 5;
}
```

Commit and push grimoire.

## 2. Pull Protos into Onion

```bash
make proto
```

This updates the grimoire submodule and regenerates Go types into `internal/platform/models/proto/generated/`.

## 3. Create the Module Structure

**Shared module** — `internal/modules/<name>/`:

```
internal/modules/<name>/
├── module.go
├── sql/
│   ├── sqlc.yaml
│   └── queries/<name>.sql
└── internal/
    ├── domain/
    │   └── <entity>.go
    ├── application/
    │   └── service.go
    ├── infrastructure/
    │   ├── repository.go
    │   └── persistence/sqlc/    ← auto-generated by sqlc
    └── routes/
        ├── routes.go
        └── handlers/
            └── <handler>.go
```

For a **platform-specific module**, use `internal/platforms/<platform>/<name>/` with the same structure.

## 4. SQL Schema + Queries

### Schema

Add the table definition in `internal/platform/database/schemas/<db>/`:

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    full_name TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Queries

Add SQLC queries in `<module>/sql/queries/<name>.sql`:

```sql
-- name: CreateUser :one
INSERT INTO users (email, password_hash, full_name)
VALUES ($1, $2, $3) RETURNING *;

-- name: GetUserByEmail :one
SELECT * FROM users WHERE email = $1;
```

### SQLC Config

Create `<module>/sql/sqlc.yaml`:

```yaml
version: "2"
sql:
  - engine: "postgresql"
    queries: "queries"
    schema:
      - "../../../../../internal/platform/database/schemas/<db>"
    gen:
      go:
        package: "sqlc"
        out: "../internal/infrastructure/persistence/sqlc"
        sql_package: "pgx/v5"
        emit_json_tags: true
        emit_db_tags: true
```

> Adjust the relative path to `schemas/` based on how deep your module is. The build script auto-discovers all `sqlc.yaml` files under `internal/modules/` and `internal/platforms/`.

Run `make generate` or let `make build` handle it.

## 5. Domain

`internal/<path>/internal/domain/<entity>.go`

Plain struct with a `FromRows` method that maps from SQLC-generated types:

```go
type User struct {
    ID    int32
    Email string
}

func (u *User) FromRows(row sqlc.User) {
    u.ID = row.ID
    u.Email = row.Email
}
```

## 6. Infrastructure (Repository)

`internal/<path>/internal/infrastructure/repository.go`

Database access layer using SQLC queries and the generic read/write executors:

```go
type Repository struct {
    queries *sqlc.Queries
    pool    *pgxpool.Pool
}

func NewRepository(_ context.Context) *Repository {
    pool := dbclient.Pool()
    return &Repository{
        queries: sqlc.New(pool),
        pool:    pool,
    }
}

func (r *Repository) GetUserByEmail(ctx context.Context, email string) (*domain.User, error) {
    user, err := db.NewReadExecutor[domain.User, sqlc.User](db.MainDatabase).
        Fetch(ctx, r.queries.GetUserByEmail, email)
    if err != nil {
        return nil, err
    }
    return &user, nil
}
```

## 7. Application (Service)

`internal/<path>/internal/application/service.go`

Business logic layer. Calls the repository, handles validation, orchestrates operations:

```go
type Service struct {
    repo *infrastructure.Repository
}

func NewService(ctx context.Context) *Service {
    return &Service{repo: infrastructure.NewRepository(ctx)}
}

func (s *Service) Authenticate(ctx context.Context, email, password string) (int64, error) {
    user, err := s.repo.GetUserByEmail(ctx, strings.ToLower(email))
    if err != nil {
        return 0, ErrInvalidCredentials
    }
    if !passwordutils.CheckPasswordHash(password, user.PasswordHash) {
        return 0, ErrInvalidCredentials
    }
    return int64(user.ID), nil
}
```

## 8. Handler

`internal/<path>/internal/routes/handlers/<handler>.go`

HTTP handler using proto request/response types. Each handler defines its routes and implements the `Serve` method:

```go
func LoginRoutes() []string {
    return []string{"/login", "/auth/login"}
}

type LoginHandler struct {
    UserService *application.Service
}

func (h *LoginHandler) Serve(ctx context.Context, req *accountv1.LoginRequest) (accountv1.LoginResponse, *errorModels.ServerError) {
    userId, err := h.UserService.Authenticate(ctx, req.Email, req.Password)
    if err != nil {
        return accountv1.LoginResponse{}, &errorModels.ServerError{
            Code:    http.StatusUnauthorized,
            Message: "Invalid email or password",
        }
    }

    token, _ := h.UserService.GenerateToken(ctx, userId)

    return accountv1.LoginResponse{
        Token:  token,
        UserId: userId,
    }, nil
}
```

**Optional validation** — add a `Validate` method for pre-handler input validation:

```go
func (h *RegisterHandler) Validate(_ context.Context, req *accountv1.RegisterRequest) *errorModels.ServerError {
    if req.Email == "" || req.Password == "" {
        return &errorModels.ServerError{
            Code:    http.StatusBadRequest,
            Message: "Email and password are required",
        }
    }
    return nil
}
```

Use `RegisterPOSTWithValidation` instead of `RegisterPOST` for handlers with validation.

## 9. Route Registration

`internal/<path>/internal/routes/routes.go`

Registers handlers with the Chi router using the generic registration helpers:

```go
func RegisterRoutes(ctx context.Context, router *chi.Mux, service *application.Service) {
    http.RegisterPOST[accountv1.LoginRequest, accountv1.LoginResponse](
        ctx, router, handlers.LoginRoutes(),
        &handlers.LoginHandler{UserService: service},
    )

    http.RegisterPOSTWithValidation[accountv1.RegisterRequest, accountv1.RegisterResponse](
        ctx, router, handlers.RegisterRoutes(),
        &handlers.RegisterHandler{UserService: service},
    )

    http.RegisterGET[accountv1.GetProfileRequest, accountv1.GetProfileResponse](
        ctx, router, handlers.AccountRoutes(),
        &handlers.AccountHandler{UserService: service},
    )
}
```

**Available registration methods:**
- `http.RegisterGET` — GET endpoint
- `http.RegisterPOST` — POST endpoint
- `http.RegisterPOSTWithValidation` — POST with `Validate` method called before `Serve`

## 10. Module Entry Point

`internal/<path>/module.go`

Wires everything together and exposes the module to the application:

```go
type Module struct {
    UserService *application.Service
}

func NewModule(ctx context.Context) *Module {
    service := application.NewService(ctx)
    return &Module{UserService: service}
}

func (m *Module) RegisterRoutes(ctx context.Context, router *chi.Mux, _ ...interface{}) {
    routes.RegisterRoutes(ctx, router, m.UserService)
}

func (m *Module) GetAnonymousRoutes() []string {
    return sliceutils.Concat(
        handlers.LoginRoutes(),
        handlers.RegisterRoutes(),
    )
}
```

- `RegisterRoutes` — called by the module registry to register all HTTP routes
- `GetAnonymousRoutes` — returns routes that don't require authentication

## 11. Wire into the Server

### Shared modules

Add to the modules struct in `cmd/api/main.go`:

```go
type apiModules struct {
    User   *user.Module
    Config *config.Module
}
```

### Platform modules

Add to the platform struct (e.g., `internal/platforms/voxire/platform.go`):

```go
type Platform struct {
    Careers *careers.Module
}

func NewPlatform(ctx context.Context) *Platform {
    return &Platform{Careers: careers.NewModule(ctx)}
}
```

Then add the platform to the API modules struct:

```go
type apiModules struct {
    User   *user.Module
    Voxire *voxire.Platform
}
```

The `AutoRegisterRoutes` function discovers modules via reflection. It recurses into platform structs automatically — no manual delegation needed.

## 12. Build

```bash
make build
```

This runs the full pipeline:
1. SQL case check
2. SQLC code generation (auto-discovers all modules + platforms)
3. Proto file generation
4. `go vet`
5. Build all binaries (api, worker, pay)
6. `golangci-lint`
