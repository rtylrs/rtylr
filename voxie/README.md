# voxie

API contracts for the rtylr platform. Voxie is the source of truth for API request and response shapes shared by the TypeScript frontend and Go backend.

Contracts are written in [TypeSpec](https://typespec.io) and compiled with [onekit](https://github.com/1homsi/onekit)'s `onkt` CLI. The `@onkt/typespec` emitter adds onekit's decorators (`@Onkt.required`, `@Onkt.http`, ...); `api/main.tsp` imports every contract. Protocol Buffers and onekit's former `.onk` language have both been retired.

The toolchain is pinned in `package.json`/`package-lock.json` (`@onkt/cli`, `@onkt/typespec`, `@typespec/compiler`, `@typespec/http`), so local builds, CI and the onion Docker images all generate with the same versions. Keep `@onkt/cli` and `@onkt/typespec` on the same version. Generating needs Node.js 22+.

## Structure

```text
voxie/
  api/               # TypeSpec contracts, one directory per service (main.tsp imports them all)
    hub/business/v1/
    hub/config/v1/    # references business/v1.Business - a cross-package reference
    ...
  gen/go/            # generated Go types, validation, HTTP server, and client (gitignored)
  gen/ts/            # generated TypeScript types, HTTP client, and validation metadata (gitignored)
  gen/openapi/       # generated OpenAPI 3.1 specs, YAML and JSON (gitignored)
```

The base HTTP path for a service is its interface's `@route`, or, without one, is inferred from its schema directory (kebab-casing multi-word segments, e.g. `hr/time_entry` → `/hr/time-entry`). Cross-directory type references resolve automatically by name, with no import statement needed.

`pos/orders/v1`'s `OrderService` deliberately has no `@route`: `pos/orders/compat/v1` re-declares its `GET /pos/orders/v1/orders` with a different request shape for Dash, and onkt only lets two services share a route when one of them takes its base path from the directory. Don't add `@route("/pos/orders/v1")` back to it.

In `/** */` doc comments, write a literal `@` as `\@` (`\@http`, `\@required`): TypeSpec reads an unescaped `@word` as a doc tag and drops the rest of the comment from the generated docs.

`voxie/` is an in-tree module of the rtylr monorepo. `onion` consumes `gen/go` through the `github.com/voxire/voxie` module (a `replace` directive in `services/onion/go.mod`); the frontends consume the TypeScript half through the `@voxire/voxie` workspace package at `clients/packages/contracts` (`make generate` copies it there). Neither output is committed — `make generate` produces it locally and CI produces it before building.

## Usage

```bash
make generate   # npm ci, then regenerates gen/ from api/**/*.tsp; output is gitignored, never commit it
make typecheck  # typechecks the generated TypeScript output
```

OpenAPI generation is enabled by `[generate.openapi]` in `onkt.toml`.
`make generate` writes YAML/JSON specs per service under the matching schema
directory, for example `gen/openapi/hub/business/v1/openapi.yaml` and
`openapi.json`. Each document includes that service’s routes and its referenced
types, including shared types. Directories with multiple services use
`<ServiceName>.openapi.yaml` and `<ServiceName>.openapi.json`.

## Adding or Changing Contracts

1. Create or edit `api/{app-or-common}/{domain}/v1/models.tsp` and `service.tsp`; a new file must also be imported from `api/main.tsp`.
2. Run `npx onkt check` to validate, then `make generate` to regenerate `gen/go`/`gen/ts`. `npx tsp format "api/**/*.tsp"` formats contracts.
3. Prove it end-to-end in the same change: compile the generated Go (`go build ./...` in `services/onion`), spin up the server with a test implementation, and exercise it over real HTTP - don't just confirm it generates without errors.
4. Run `pnpm --filter @voxire/voxie typecheck` and the affected app typechecks. The contract, generated consumers and Go handlers belong in one commit; `gen/` never is.

## Known gaps

- **Frontend validation metadata** (`gen/ts/validation/metadata.ts`) was generated by scanning `proto/`'s `buf.validate` annotations; that scanner has no TypeSpec-aware equivalent yet, so it now always produces empty metadata (it still type-checks - see the comment on `scripts/generate_validation_metadata.py`'s `--proto-root` default). Needs a decorator-aware generator as follow-up work before frontend field validation is restored.
- **Cross-field validation**: a proto message-level constraint like `buf.validate.message.oneof` ("exactly one of these fields is required") was not carried over as an `@Onkt.rule`. The one occurrence found during migration (`flow.task.v1.ListTasksRequest`) was translated with both fields left optional and no cross-field check - needs a hand-written check in the handler.

## Tools

- `onkt` (github.com/1homsi/onekit, npm `@onkt/cli`) generates Go/TypeScript types, validation, HTTP server, and client code and OpenAPI from the TypeSpec contracts in `api/`, configured by `onkt.toml`.
- the `@voxire/voxie` workspace package exposes the generated TypeScript to the frontends.
