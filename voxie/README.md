# voxie

API contracts for the rtylr platform. Voxie is the source of truth for API request and response shapes shared by the TypeScript frontend and Go backend.

Contracts are written in [onekit](https://github.com/1homsi/onekit)'s `.onk` schema language and compiled with the `onek` CLI. Protocol Buffers (`proto/`, `buf`) have been fully retired - every service has been migrated onto `.onk`.

## Structure

```text
voxie/
  api/               # .onk contracts, one directory per service
    hub/business/v1/
    hub/config/v1/    # references business/v1.Business - a cross-package reference
    ...
  gen/go/            # generated Go types, validation, HTTP server, and client
  gen/ts/            # generated TypeScript types, HTTP client, and validation metadata
```

The base HTTP path for a service is inferred from its schema directory (kebab-casing multi-word segments, e.g. `hr/time_entry` → `/hr/time-entry`) - no `base_path` needed unless the route is irregular. Cross-directory type references resolve automatically by name, with no import statement needed.

Go output (`gen/go`) is generated here and committed — `onion` consumes it directly from the submodule checkout, no local generation needed. `rtylr` still generates its own TypeScript: `pnpm contracts:sync` into `packages/contracts/src`.

## Usage

```bash
make generate   # regenerates gen/go and gen/ts from api/*.onk — commit the result
make typecheck  # typechecks the generated TypeScript output
```

## Adding or Changing Contracts

1. Create or edit `api/{app-or-common}/{domain}/v1/models.onk` and `service.onk`.
2. Run `onek check .` to validate, then `make generate` to regenerate `gen/go`/`gen/ts`.
3. Commit, and prove it end-to-end: compile the generated Go, spin up the server with a test implementation, and exercise it over real HTTP - don't just confirm it generates without errors.
4. Update the Voxie submodule pointer in `onion` and `rtylr`; run `pnpm contracts:sync` in `rtylr`.

## Known gaps

- **Frontend validation metadata** (`gen/ts/validation/metadata.ts`) was generated by scanning `proto/`'s `buf.validate` annotations; that scanner has no `.onk`-aware equivalent yet, so it now always produces empty metadata (it still type-checks - see the comment on `scripts/generate_validation_metadata.py`'s `--proto-root` default). Needs a decorator-aware generator as follow-up work before frontend field validation is restored.
- **Cross-field validation**: a proto message-level constraint like `buf.validate.message.oneof` ("exactly one of these fields is required") has no onk decorator equivalent. The one occurrence found during migration (`flow.task.v1.ListTasksRequest`) was translated with both fields left optional and no cross-field check - needs a hand-written check in the handler.

## Tools

- `onekit`/`onek` (github.com/1homsi/onekit) generates Go/TypeScript types, validation, HTTP server, and client code from `.onk` contracts in `api/`.
- `rtylr` owns its own TypeScript code generation.
